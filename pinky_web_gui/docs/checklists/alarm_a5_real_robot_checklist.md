# 알람바 Step A5 실물 확인 체크리스트 (사용자 수행)

> 역할: 알람 카탈로그 수정(Step A5)을 **실제 로봇의 알람과 스피커로** 확인하는 순서. mock 으로는 `tests/test_alarmcatalog_edit.py`(권한, 검증, 되돌리기, 재시작 유지, 끈 알람)와 `tests/verify_alarm_edit_ui.py`(화면, 소리 호출 횟수)가 통과했다. 이 문서의 항목은 아직 사람이 실제 로봇과 소리로 해 보지 않았다.
> 규칙은 `../interfaces.md` 6-7절 "알람 카탈로그", 계획은 `../prd/Pinky 알람바 개선 — 단계별 PRD.md` Step A5.

> 로봇이 움직일 수 있는 항목은 주변을 비우고 전원 스위치에 손이 닿는 곳에서 한다. 소리를 크게 켜기 전에 음량을 낮춰 둔다.

## 사전 조건
- [ ] 관제 PC: `export ROS_DOMAIN_ID=50` 후 `.venv/bin/python -m backend.main` (**`--mock` 없이**, 인증 켬). 브라우저 두 개를 열어 하나는 `mngr`, 하나는 `oper` 로 로그인한다 (`http://localhost:8000/`).
- [ ] `config/sounds/` 에 소리 파일이 2개 이상 있다 (예: 서로 다른 소리). 소리 설정(`알람` 화면의 `알람소리` 버튼)에서 레벨마다 다른 파일을 골라 둔다.

## A. 권한
| # | 방법 | 기대 | 결과 |
|---|---|---|---|
| 1 | `oper` 브라우저에서 `알람` → `카탈로그` | 표는 보이지만 `편집` 열과 버튼이 없다 | |
| 2 | `oper` 로 Chrome 개발자 도구에서 PUT 직접 호출 | 403 `알람 카탈로그는 manager 만 바꿀 수 있습니다` | |
| 3 | `mngr` 브라우저에서 같은 화면 | 모든 행에 `편집` 버튼이 있다 | |

## B. 끄기·켜기·레벨 (실제 알람으로)
| # | 방법 | 기대 | 결과 |
|---|---|---|---|
| 1 | `mngr`: `ROBOT_OFFLINE` 의 편집 → 사용 끄기 → 저장 | 두 브라우저 모두 표에서 흐리게(꺼짐). 이미 떠 있던 오프라인 알람이 있으면 해소되고 소리가 멈춘다 | |
| 2 | 로봇 전원을 끈다 (5초) | **알람바에 오프라인 알람이 생기지 않고** 소리도 나지 않는다 | |
| 3 | 다시 켠다: 사용을 켜고 저장, 로봇 전원을 다시 껐다 켠다 | 오프라인 알람과 소리가 다시 난다 | |
| 4 | `CMD_REJECTED`(L)를 H 로 올리고 저장, 허용 안 된 명령 | 새 알람이 H(빨강)로 뜨고 H 소리가 난다. 전에 떠 있던 행은 그대로 L | |
| 5 | `기본값으로 되돌리기` | 표가 L 로 돌아오고 ID 옆 `•` 가 사라진다 | |
| 6 | `mngr` 이 바꾸면 `oper` 브라우저 | 새로고침 없이 같은 변경이 보인다 | |

## C. 알람별 소리
- [ ] `CMD_REJECTED` 의 사운드 파일을 다른 파일로 고르고 반복 주기를 2 로: 그 알람이 뜨면 **고른 파일**로 약 2초마다 반복된다 (레벨 파일이 아니라).
- [ ] 같은 알람에서 소리를 끄면: 알람바에는 보이지만 소리가 나지 않고 SIL 버튼이 눌리지 않는다.
- [ ] 사운드 파일을 `레벨 기본` 로 되돌리면 레벨 파일(또는 합성음)로 난다. 파일을 `config/sounds/` 에서 지우면 합성음으로 난다.
- [ ] 브라우저 알람 중 소리가 나는 것은 `SERVER_DISCONNECTED` 뿐이다 (서버를 끄면 난다). 나머지 브라우저 알람(요청 실패 등)은 소리 칸이 잠겨 있다.

## D. 비상정지 알람 보호
- [ ] `ESTOP_FAILED`, `ESTOP_PARTIAL`, `ESTOP_REQUEST_FAILED` 의 편집에서 사용, 레벨이 잠겨 있고 안내 문구가 있다. (개발자 도구로 PUT 해도 400 `This alarm cannot be disabled` 등.)
- [ ] 브리지를 끄고 `비상 정지` 를 누르면 `... 비상정지 실패: ...` 알람(HH)과 소리가 나온다 (끄려 해도 꺼지지 않았다).

## E. 저장과 기록
- [ ] 서버를 껐다 켜도 B-4 의 변경이 남아 있다 (`config/alarms.local.yaml` 에 바꾼 항목만 있다).
- [ ] `config/alarms.yaml` 은 GUI 로 바꿔도 그대로다 (`git diff config/alarms.yaml`).
- [ ] 로그 화면의 `GUI 서버` 탭에 `알람 카탈로그 변경 (mngr): ...` (끈 것은 WARN), `알람 카탈로그 되돌리기 (mngr)` 가 시각과 함께 남는다. 잘못된 입력으로 저장하면 `change rejected for ... by mngr: ...` 가 남는다.
- [ ] 메시지 입력: 빈 칸, 121글자, 모르는 `{자리표시자}` 는 대화상자에 한국어 오류가 나고 저장되지 않는다. 한글 문구도 저장된다.

## 프로세스 실패 알람 (PROC_FAILED)

| # | 할 일 | 기대 | 결과 |
|---|---|---|---|
| P1 | 꺼 둔 로봇의 프로세스(예: bringup)를 시스템 패널에서 `시작` | 오류 문구와 함께 알람바에 `PROC_FAILED`(H): `<프로세스> 실패: …`. 같은 사건의 알람이 두 줄로 뜨지 않는다 | |
| P2 | 같은 프로세스를 다시 `시작` | 이전 알람이 해소(`해소 HH:MM:SS`)로 바뀌고, 또 실패하면 새 행 | |
| P3 | 정상 실행 중인 프로세스를 로봇 쪽에서 강제로 종료 | `예기치 않게 종료됨` 사유로 `PROC_FAILED` | |
| P4 | `알람` → `카탈로그` → `PROC_FAILED` 를 `사용` 끔 후 P1 | 서버 알람은 없고, 화면의 `PROC_REQUEST_FAILED` 가 대신 알린다 | |
