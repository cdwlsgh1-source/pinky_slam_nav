# Step 4 실물 로봇 체크리스트 (사용자 수행)

mock 으로는 `pytest`, `tests/verify_step4_mock.py`, `tests/verify_step4_ui.py` 가, 로봇과 분리한 격리 도메인(77, localhost 전용)에서는 `tests/verify_step4_ros.py` 가 통과했다. 아래는 **실제 로봇에서만** 확인되는 항목이다. 이 문서의 어떤 항목도 아직 실행되지 않았다.

> **GUI 비상정지는 소프트웨어 정지이며 하드웨어 비상정지를 대체하지 않는다.** 모든 시험에서 전원 스위치에 손이 닿는 곳에 사람이 있어야 한다. **B~E 가 모두 통과하기 전에는 GUI 비상정지를 안전장치로 믿지 않는다** (PRD). 하나라도 실패하면 원인(`cmd_vel` 경합 등)을 해결한 뒤 다시 시험한다.
> 로봇이 예상과 다르게 움직이면 즉시 전원을 끈다.

통과/실패와 이상한 화면 캡처, 백엔드 로그(`backend`, `backend.motion`, `backend.ros`), `ros2 topic echo` 결과를 알려 주면 된다.

## 알려진 한계 (이 단계에서 의도한 것)
- 소프트웨어 정지이며 하드웨어 비상정지가 아니다.
- `cmd_vel` 은 여러 노드가 낼 수 있어 마지막 발행이 이긴다 (D, E 항목).
- 백엔드가 `kill -9` 로 죽거나 PC 가 꺼지면 0 속도를 보낼 수 없다 (17번에서 로봇 쪽 타임아웃을 확인).
- 구역 상태는 매니저가 바뀔 때만 발행하므로, 구역 점유 중에 백엔드를 켜면 다음 변화 전까지 "상태 수신 전"이다.
- 경로 선과 진행 문구는 이 서버가 보낸 `start`/`goto` 만 안다 (`last_task` 는 메모리, 서버를 껐다 켜면 사라진다).
- LiDAR 점은 `amcl_pose` 기준이며 센서와 로봇 중심의 오프셋을 무시한다.
